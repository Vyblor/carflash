## 정해진 것 (2026-11-05 창업자 답)

- 화면은 Kotlin + Jetpack Compose, 해치 3D는 WebView 안의 three.js(마스코트 리그 재사용).
- 서버는 이번에는 만들지 않는다. 코드 공유·플래시몹 초대는 앱 안 목업 저장소와 가짜 참가 차로 흐름을 완성한다.

- 커밋 신원은 `Haechi <225294644+Vyblor@users.noreply.github.com>`이다(2026-11-05 창업자). 저장소는 창업자 개인 계정에 둔다. 커밋은 창업자가 지시할 때 한다.

## E2E 시험 방식

에뮬레이터(Pleos Connect v2.1.0, AVD `Pleos_Probe`)에 앱을 설치하고, `e2e/` 의 Python 스크립트가 adb로 화면을 조작한다. 화면 요소는 Compose `testTag`를 resource-id로 내보내(`testTagsAsResourceId`) `uiautomator dump`로 찾는다. 차량 쪽 결과는 버추얼 콘솔 HTTP(`/vehicle/state`)로 확인하고, 기어는 콘솔 `/vehicle/gear`로 바꾼다. 스프린트마다 시험 스크립트 하나(`e2e/sN_*.py`)를 쓰고, 다음 스프린트에서는 앞 스프린트 시험도 다시 돌린다(회귀).

### S1 — 통과 (2026-11-05)

만든 것은 다음과 같다. Gradle 프로젝트(AGP 8.5.0, Kotlin 1.9.24, Compose BOM 2024.06.00, compileSdk 34, minSdk 28, `ai.pleos.playground:Vehicle:2.3.2`)를 세웠다. 디자인 토큰은 `ui/theme/Theme.kt`에 옮겼고 글꼴은 Asta Sans 가변 글꼴이다. 공통 컴포넌트는 상단줄, 기어 칩, 버튼, 타일, 커버, 효과 배지, 해치 뷰다. 화면은 A1 첫 실행(안전 약속 3줄과 이 차에서 쓸 수 있는 효과)과 A2 홈(가로·세로 배치)을 만들었다. 차량 게이트웨이는 Pleos 구현과 가짜 구현 두 가지다. 해치는 WebView 하나에 three.js를 올리고 화면이 바뀌면 그 WebView를 옮겨 붙인다. 시험 도구는 `e2e/lib.py`이고 S1 시험은 `e2e/s1_onboard_home.py`다. S2를 위해 곡 5개(`tools/make_songs.py`, 모두 수식 합성)를 미리 만들어 두었다.

시험 결과는 22개 항목 모두 PASS다(에뮬레이터 Pleos_Probe, 2026-11-05). `EXTRACTED`
- 첫 실행에 A1이 뜨고, "알겠어요, 시작"을 누르면 A2로 간다. 앱을 다시 켜면 A1을 건너뛴다.
- 효과 점검에서 조명·창문·와이퍼·송풍이 모두 지원으로 나온다.
- 기어 칩이 P를 보여 준다. 콘솔에서 D와 P로 바꾸면 앱이 받는다.
- 해치 WebView는 WebGL 2.0 컨텍스트에서 그려지고, hello에서 idle로 바뀐다. 홈에서 해치 프레임은 53 fps다.
- 화면 사진은 `e2e/out/s1_a1_onboard.png`와 `e2e/out/s1_a2_home.png`(git에서 제외)다.

시험 중 고친 것:
- 콘솔 기어 변경이 503 `emulator_inactive`로 막혔다. 원인은 하트비트 스크립트가 꺼져 있던 것이었고, 켠 뒤 통과했다.
- Vehicle SDK 조회 API 이름이 `getWindowPosition`이 아니라 `getCurrentXxx` 꼴이었다. 공식 샘플 앱 가이드의 `getCurrentDoorPosition` 규칙을 보고 맞췄다. SDK 바이너리는 열지 않았다.
- 에뮬레이터는 앰비언트 조명 영역을 1개로 돌려준다. 그래서 효과 점검의 "앰비언트 1구역" 표시를, 영역이 1개일 때는 "앰비언트 조명"으로 바꿨다.

남은 것:
- 세로(840) 배치는 코드로만 있고 에뮬레이터 분할 화면에서는 아직 시험하지 않았다. S6 회귀에서 시험한다.
- 디버그 APK가 65 MB다(아이콘 라이브러리를 줄이지 않았다). 출품 전에 R8로 줄인다.
- 커버 그림은 아직 그라데이션이다. 해치 커버는 S2에서 넣는다.
- `INFERRED` 앰비언트 영역 1개는 SDK가 좌석 5구역을 영역 하나로 묶어 돌려주는 것으로 보인다. 구역별 색 연출이 가능한지는 S2에서 시험한다.

### S2 — 통과 (2026-11-05)

만든 것은 다음과 같다. 플래시몹 데이터(`data/ShowRepository.kt`, `data/Codec.kt`)는 추천 5개(캠핑장의 밤 206 518, 로맨틱 드라이브 731 204, 감미로운 밤 482 915, 생일 축하 120 120, 비 오는 주차장 880 088)와 구간별 연출 계획(`SectionPlan`)을 가진다. 계획이 비어 있으면 `Designer.auto`가 곡 구간 이름(intro, verse, build, drop, chorus, break, bridge, outro)으로 색 패턴·창문·와이퍼·송풍을 채운다. 엔진(`show/ShowEngine.kt`)은 곡 재생 위치 하나를 시계로 써서 박자마다 `Timeline.frame`을 만들고, 바뀐 값만 차에 보낸다. 시작 직전 차 상태를 찍어 두고 끝·정지·기어 변경 때 그대로 되돌린다. 창문은 최대 60%(`WINDOW_LIMIT`)다. 화면은 A3 준비(효과 스위치, 창문 경고, 첫 장면 미리보기), A4 카운트다운, A5 재생(지금 움직이는 것, 차 지도, 해치 춤), A6 끝·코드다. 커버 5장은 마스코트 포즈 렌더(`ideas/carflash-mascot/out/poses-1024/`)를 테마 배경에 얹어 `tools/make_covers.py`로 만들었다. 홈의 큰 타일에는 움직이는 해치가 따로 올라가므로 해치 없는 배경판(`_bg.jpg`)을 쓴다.

시험 결과는 27개 항목 모두 PASS다(`e2e/s2_show.py`). `EXTRACTED`
- 캠핑장의 밤 재생 중 콘솔 조명 색이 #ff8a00, #ffd60a, #ff2d55, #a05cff 4가지로 바뀌고, 드롭(16마디)에서 창문이 60%까지 열리고, 송풍이 1·2·4·5단으로 바뀐다.
- 정지를 누르면 0.3초 안에 조명·창문·송풍이 시작 전 값으로 돌아간다.
- 생일 축하(46초)를 끝까지 틀면 후렴에서 와이퍼가 Low로 움직이고, 끝나면 A6에 코드 120 120이 나오고 와이퍼·송풍·색이 원래대로 돌아간다. 해치는 cheer로 바뀐다.

시험 중 고친 것:
- 재생 중 `uiautomator dump`가 15~35초 걸렸다. 원인은 100 ms마다 바뀌는 진행 막대 너비와 차 지도 설명문이 접근성 "서브트리 변경" 이벤트를 쏟아낸 것이다(6초에 28건 측정). 진행 막대는 그리기만 바꾸고, 차 지도 설명은 재생 중 고정했다. 그 뒤 dump는 2.1초, 이벤트는 0건이다. 이 수정은 실차 화면 읽기(접근성) 부담도 줄인다. `EXTRACTED`
- 카운트다운 3초 안에 화면을 두 번 읽을 수 없어서, 디버그 빌드에만 `cf_countdown_ms` 시험 옵션을 넣었다(출시 빌드에서는 무시).
- 앞선 시험에서 정지 뒤 조명이 원래 보라색이 아니라 흰색으로 돌아간 적이 있다. 시작 전 상태 조회가 한 번 실패하면 기본값(흰색)으로 되돌렸기 때문으로 보고(`INFERRED`), 조회를 한 번 더 시도하게 했다. 시험 도구는 매번 조명을 보라색으로 맞춰 두고 시작해, 원래 색 복원을 가려낼 수 있게 했다.
- 카운트다운 화면에서 해치와 차 지도가 겹쳐 크기를 줄였다. 끝 화면 복원 문구를 실제 켠 효과로 만든다(예: "조명·와이퍼·송풍은 …").

### S3 — 통과 (2026-11-05)

만든 것은 다음과 같다.
- E1: 기어가 P가 아니면(카운트다운 중 포함) 엔진이 바로 멈추고 되돌린다. 플래시몹 동안 포그라운드 서비스(`show/ShowService.kt`, specialUse)를 켜서 주행 차단 화면이 앱을 가려도 프로세스가 살아 있게 했다.
- E2: 멈춘 이유, 멈춘 위치("「캠핑장의 밤」 0:31에서 멈췄어요"), 되돌린 내용("조명 원래 색 · 창문 닫힘 · 송풍 원래 단")을 보여 주고 "처음부터 다시"와 "닫기"만 둔다.
- E3: 배터리 잔량을 Vehicle SDK `getEvBattery().getEvBatteryStateOfCharge`로 3초마다 읽는다(권한 `CAR_ENERGY` 추가). 20% 미만이면 창문·송풍을 끄고 조명 밝기를 70%로 제한해 시작한다. 10% 미만이면 시작 버튼을 끈다. 재생 중 10% 아래로 떨어지거나, 20% 아래인데 창문·송풍을 쓰는 중이면 멈춘다.
- E4: 연결 상태를 `ConnectivityManager`로 본다. 끊기면 홈에 배너를 띄우고 코드·초대 타일을 끈다. 추천 플래시몹과 만들기는 그대로 쓸 수 있다.

시험 결과는 32개 항목 모두 PASS다(`e2e/s3_safety.py`, 첫 실행에 통과). `EXTRACTED`
- 드롭 구간 재생 중 콘솔에서 기어를 D로 바꾸면 0.13초 안에 콘솔의 조명·창문·송풍이 시작 전 값이 된다. 엔진 로그의 복원 명령 소요는 22 ms다. 합격선 1초를 넘지 않는다.
- D에서는 시스템이 "주행 중에는 사용할 수 없습니다" 화면을 띄운다(카플래시가 그리지 않음). 다시 P로 바꾸고 앱을 열면 E2가 나온다.
- 카운트다운 중 D로 바꾸면 곡이 시작되지 않고 차는 그대로다.
- 콘솔에서 배터리를 15%로 두면 준비 화면에 배너가 뜨고 창문·송풍이 꺼지며, 재생 중 밝기는 70%, 창문은 0이다. 5%면 시작 버튼이 꺼진다. 재생 중 8%로 떨어뜨리면 멈추고 되돌린다.
- 오프라인에서 배너, 코드·초대 타일 꺼짐, 만들기 켜짐을 확인했다.

한계:
- `INFERRED` 배터리 기준값 20%·10%는 실차 정보 없이 정한 임시 값이다. 12V 배터리 값은 문서에서 찾지 못해 EV SOC만 쓴다.
- `INFERRED` 에뮬레이터는 SOC를 %로 돌려준다(콘솔 15 → 앱 15). 실차 단위는 확인하지 않았다.
- 오프라인 시험은 디버그 옵션 `cf_offline`으로 흉내 냈다. 실제 연결 끊김 감지 코드는 같은 상태값을 쓰지만, 에뮬레이터 네트워크를 실제로 끊어 보지는 않았다.

### S4 — 통과 (2026-11-05)

만든 것은 다음과 같다.
- 코드 서버 목업(`data/MockShowServer.kt`): 추천 5개, 이 기기에서 만든 내 플래시몹, "다른 차(조명 5구역)에서 만든" 친구 플래시몹 2개(불꽃 세레나데 415 926, 별 헤는 캠프 314 159)의 코드를 안다. 저장하면 쓰이지 않은 6자리 코드를 새로 준다.
- B1 코드 입력: 숫자 키패드(키 높이 120)만 쓰고, 6번째 숫자에서 바로 찾는다. 찾으면 이름을 1초 보여 주고 준비 화면으로 간다. landscape에서는 키패드가 왼쪽(운전석 쪽)이다. 최근 코드 칩은 3개다.

- 차 그림에 앞 전조등 2개·뒤 미등 2개를 그렸다. 전조등은 흰빛과 빛 번짐, 미등은 앞 호박색, 둘 다 뒤는 빨강, 끔은 회색이다. 앞유리 아래 와이퍼 날 2개도 그렸다. 움직이면 비스듬히 선 청록, 쉬면 누운 회색이다.
- 효과 아이콘 배지(`EffectBadge`)를 만들어 차 그림의 해당 부분 위에 얹었다. 전조등은 앞 범퍼, 와이퍼는 앞유리, 조명은 실내 가운데, 창문은 왼쪽 창 사이, 송풍은 뒷좌석 앞(단 수 옆)이다. 움직이는 효과는 청록으로 채우고, 쉬는 효과는 테두리만 둔다. 준비 화면·카운트다운·편집기 그림에도 같은 배지가 붙는다(너비 200 dp 미만 그림에는 생략).
- 왼쪽 목록을 "지금 차에서 움직이는 것"으로 바꿨다. 켠 효과마다 한 줄씩 [같은 배지 · 효과 이름 · 지금 하는 일]을 보여 준다. 이 구간에서 쉬는 효과도 "쉬는 중"으로 남겨, 그림과 늘 짝지어 볼 수 있다. 조명 줄에는 지금 색 점이 붙는다.
- 문구는 구간 안에서 바뀌지 않게 했다(박자마다 바뀌면 접근성 이벤트가 쏟아져 S2에서 겪은 느려짐이 다시 생긴다). 전조등 깜빡임 자체는 그림에서만 박자마다 바뀐다.

시험: `s7_headlamp.py`에 5개 항목을 더했다(왼쪽 줄 = 켠 효과, 전조등 줄 문구, 배지 4개, 비 오는 주차장은 조명·와이퍼 줄과 배지만). S7 단독 20개 항목이 모두 PASS다. 전체 회귀(S1~S7)는 195개 항목이 모두 PASS다. 해치 프레임은 홈 50·51·50, 재생 50·52·55 fps다(2026-11-07). `EXTRACTED`

## 수동 시험 안내 (창업자)

에뮬레이터 `Pleos_Probe`를 켜고 `adb install -r -g app/build/outputs/apk/debug/app-debug.apk`로 설치한다. 버추얼 콘솔(`http://127.0.0.1:8088`)과 하트비트 스크립트(`contest/probe-app/tools/console-heartbeat.sh`)가 있어야 기어·배터리를 바꿀 수 있다. 볼 흐름은 다음과 같다.

2. 재생 중 콘솔 기어 D → 차단 화면 → P → 앱 열기 → 멈춘 이유 화면.
3. 콘솔 배터리 15%, 5% → 준비 화면 배너와 시작 버튼.
4. 만들기 → 곡 → 편집(칸 탭 → 블록 탭) → 미리보기 → 저장 → 코드 → 홈 → 코드로 불러오기에 그 코드.
